# 01 リポジトリ構成と境界

規則 ID: `B1`〜`B18`。正は `vwc-rules`。各リポジトリの `docs/rules/` はその複製（手順は 05）。

## 1. 4つのリポジトリ

| リポジトリ | 役割 | ライセンス | 配備先（サーバー上） | 版ファイル（配備単位のルート） | 契約の持ち主 |
|---|---|---|---|---|---|
| `vwc-frontend` | 画面・ブラウザー向け資材 | GPL-3.0-or-later | `/editor/`（BE と重ならない場所） | `public/VERSION` | FE は契約を持たない（BE の契約の写しを持つ） |
| `vwc-backend` | 業務 API・データ・公開アプリ配信 | MIT（GPL 以外） | `/editor/system/` `/editor/file/` `/editor/app/` | `editor/system/VERSION` | FE 向け API（`docs/04_API.md`） |
| `vwc-idp` | 本人確認（IdP） | MIT（GPL 以外） [提案] | `/auth/` | `auth/VERSION` | IdP 契約（`docs/contract/IdP契約.md`） |
| `vwc-rules` | 規則の正本（文書のみ） | MIT [提案・要確認] | 配備しない | `VERSION`（規則の版） | 規則（本書を含む `rules/`） |

- 4つ目の `vwc-rules` は、バージョン・API・FE/BE/IdP の分離・統合の規則すべての正とする。 [確定]
- 規則を変えるときは `vwc-rules` を直し、各リポジトリが複製を更新する。複製を直接書き換えない。 [確定]
- `vwc-tools`（FE と BE を結合した配布用の `editor/` を置くフォルダー）は、リポジトリではなく生成物の置き場として扱う。B8 との整合は 7 章の未決事項。

## 2. 境界ルール

B1〜B11 は、BE の `docs/19_リポジトリ構成とライセンス.md` §2 から引き継ぐ（意味は変えず、IdP を加えるために対象を広げた）。B12〜B18 は新規。

| # | ルール |
|---|---|
| B1 | リポジトリ間は **HTTP だけ**でつなぐ。コード・ライブラリ・生成物を共有しない（サブモジュール、コピー、パッケージ共有もしない）。共有してよいのは**文書**だけ |
| B2 | BE と IdP のリポジトリ・配布物に、FE のファイル（HTML・JS・CSS・フォント・ヘルプ・`vendor/`・`*.wasm`）を入れない |
| B3 | FE のリポジトリ・配布物に、BE・IdP の PHP を入れない（テスト用の偽 API は FE 側で別に書く。`dev/fake-api/server.py`） |
| B4 | GPL の部品（ffmpeg コア）は FE の `vendor/ffmpeg/` だけ。触るのは `js/media.js` だけ |
| B5 | BE・IdP の依存は PHP 標準＋自作のみ。外部ライブラリを入れる場合は、MIT・BSD・Apache-2.0・ISC など寛容なライセンスに限り、GPL・LGPL・AGPL は入れない（依存台帳に記録）。IdP のパスキー検証ライブラリは、採用時に版・ライセンス・維持状況を確認する（要確認） |
| B6 | BE と IdP は FE の画面（HTML・CSS・フォント・JS）を配信も参照もしない。BE は FE のファイルを読まない（版・ビルドの計算でも）。`gate.php` は 302 とプレーンテキストだけ、`preview.php` は利用者のファイルだけを配信する。IdP の画面は IdP 自身の資材だけで作る |
| B7 | API の仕様は**文書**で共有する。型や定数をコード生成して共有しない。値（上限など）は API が返す。FE が持つのは、ツールの上限と画面設定だけ |
| B8 | 配布物は別々。「FE と BE と IdP を1つにした zip」は作らない。配備の手順は「それぞれを、重ならない場所へ置く」 |
| B9 | リポジトリをまたいでコードを移さない（FE に外部の貢献者がいる場合、GPL でしか使えないコードが混じるため）。BE と IdP の間も、独立した版管理のために避ける |
| B10 | 自作ファイルの先頭に SPDX 表記を付ける（FE: `GPL-3.0-or-later`、BE・IdP: `MIT`）。第三者の部品は元のライセンスのまま |
| B11 | FE・BE・IdP は**同じオリジン**（同じホスト名）で動かす（Cookie・CSRF・`form-action`・ポップアップ連携の前提）。別オリジン配備は対象外 |
| B12 | IdP は `/auth/` に置き、`/editor/` の中には置かない。BE の `editor/system/auth/`（IdP クライアントの入口）と混同しない |
| B13 | IdP の DB・鍵・設定は `auth/system/` の下だけに置く。BE のコードは、そのパスを参照しない（静的検査で確認） |
| B14 | BE と IdP の通信は、OIDC の認可コード＋PKCE と、BE から IdP への `state.php` の呼び出しだけ。通信の仕様は IdP 契約に書く |
| B15 | FE は IdP を直接呼ばない。FE がするのは、BE の入口（`system/auth/idp.php`）への画面遷移と、IdP が付ける `?auth=` への反応だけ |
| B16 | 管理者かどうかの**正本は IdP**。BE は IdP が返す値だけを使い、自分の DB の値を正としない。BE の `members.role` は IdP の値の写しとして扱う |
| B17 | パスワード・第2要素の秘密は IdP だけが持つ。FE と BE のコード・DB・ログに入れない |
| B18 | 規則の複製の先頭には、元（`vwc-rules` のタグ）を書く。複製の中身を書き換えない |

## 3. 配備後の見え方

```text
https://ドメイン/editor/              ← FE（GPL）の public/ の中身
   index.html  config.js  VERSION  js/ css/ fonts/ help/ vendor/  licenses.html  mermaid-frame.html  .htaccess
https://ドメイン/editor/system/       ← BE（MIT）。VERSION もここ
   api/ auth/（idp.php など）lib/ config/ data/  .htaccess
https://ドメイン/editor/file/         ← BE（実行時のデータ。直アクセス拒否）
https://ドメイン/editor/app/          ← BE（公開アプリ）
https://ドメイン/auth/                ← IdP（MIT）
   index.php  authorize.php  token.php  jwks.php  state.php  logout.php  version.php  assets/  VERSION  .htaccess
   system/（lib/ config/ data/ …。全拒否）
```

**所有表（パスの重なりを作らない）**

| パス | 持ち主 |
|---|---|
| `editor/index.html` `config.js` `VERSION` `js/` `css/` `fonts/` `help/` `vendor/` `licenses.html` `mermaid-frame.html` `.htaccess` `build-manifest.json` | FE |
| `editor/system/` `editor/file/` `editor/app/` | BE |
| `auth/`（`auth/system/` を含む） | IdP |
| サーバーのルート直下の `.htaccess` など、上記以外 | サーバー管理者（要確認。本規則の対象外） |

`editor/.htaccess` は FE が持つ。`system/` `file/` `app/` の設定は BE の `.htaccess`、`auth/` の設定は IdP の `.htaccess` が持つ。

## 4. 統合の規則

統合とは、**配備のときにだけ**3つの配布物を並べること。ソースの統合ではない。

1. 統合してよいのは配備物だけ。ソース・リポジトリ・文書を混ぜない（B1・B8）。
2. 配備の順は、後ろの層が前の層に依存する向きにする。**IdP → BE → FE**（新機能）。FE が先に新しくなると、BE にない API を呼ぶ。
3. 互換を壊す変更（MAJOR）は、BE と FE を続けて更新する。更新の合間は非互換の画面が出る（`03` §6）。
4. IdP は FE・BE の結合の対象に入れない。`/auth/` は別のフォルダーとして FTP で置く。結合ツール（`build_server_transfer.py`）は `/auth/` を触らない。
5. 配備のたびに、所有表の重なりがないこと（FE が `system/` を、BE が FE のファイルを上書きしていないこと）を確認する。
6. 設定ファイル・DB・鍵・利用者のファイルは、どのリポジトリにも入れず、配備物にも含めない。

## 5. 変更の影響表（どこを直すか）

| 変更 | 直すもの |
|---|---|
| FE 向け API の追加 | BE: レジストリ・`docs/04_API.md`・テスト → FE: 契約の写し・`api.js`・偽 API |
| BE と IdP の契約の変更（claim の追加など） | IdP: `docs/contract/IdP契約.md` → BE: 契約の写し・検証コード |
| 規則の変更 | `vwc-rules` → 各リポジトリの `docs/rules/` を更新 |
| 版を上げる | その配備単位の `VERSION`・`CHANGELOG.md`・`BUILD_REFERENCE`（`03`・`05`） |

## 6. 引き継ぎ時に最初に読む順

`vwc-rules/README.md` → 本書 → `03` → `04` → 自分が担当するリポジトリの `README.md`。
