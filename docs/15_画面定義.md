# 15 画面定義（モックが正）
状態: v3。**完成形のモック（`mock/`）が見本**。本書は、モックの画面・表示機能の要約と、モックへ追加する点（17 参照）を定義する。色・配置・余白は定義しない（モックの判断）。「モック操作」（`dev/`）は開発用で、実装に含めない。
## A. 方針
- 外部通信ゼロ。固定のサンプルデータで画面遷移・ダイアログを確認できる。本実装では `data.js` を API の結果に置き換える（`fromApi()`）。
- 対象: S01〜S21、左パネル SM01〜SM12。サンプルは 部員4名（管理者1・一般2・削除デモ1）、プロジェクト4つ＋孤立プロジェクト1つ、アプリ6つ（公開・限定公開・非公開・放置・孤立を含む）、容量 上限500MB・使用398MB（孤立分を除外）。
- 状態（モック操作で再現）: 通常/空/読込中/エラー/ロック/容量上限間近/保存競合/容量超過、管理の再認証切れ、最大アップロード超過、ZIP失敗・大きすぎ、アクセスコードのロック、カメラ許可待ち・拒否・なし、WebAssembly非対応、ffmpeg読込中・失敗、変換の中止、メンテナンス中、放置アプリ通知。
## B. 共通部品
ボタン（主/副/危険/無効/読込中）、ダイアログ（Esc・外側で閉じる。未保存警告は閉じない）、トースト（設定でON/OFF）、バッジ（公開・限定公開・非公開・孤立・放置・未追跡・この端末・閲覧のみ・編集可・公開権限・管理者）、ゲージ（80%で警告色、100%で危険色）、表（スマホはカード）、ツリー、タブ、コマンド検索、ファイル名検索、再認証ダイアログ、空状態、転送トレイ、スケルトン。

## E. 管理画面の表示（v3.1）
| 場所 | 規則 |
|---|---|
| 再認証バー（管理の全ページの上） | 「管理の再認証 あと mm:ss」と短く。右のボタン（「いま再認証する」）は従来どおり。切れているときは「管理の再認証 切れています」 |
| お知らせ一覧 | 「重要度」のバッジは改行せず、列の幅を使って1行で表示。「表示期間」は日付の期間表示の規則（09） |
| 「新しいお知らせ」ダイアログ | 下記のとおり。見出しは枠の外、枠は入力部品の1重だけ（入れ子の枠・二重の枠を作らない） |
| 制限値 | 「既定値に戻す」ボタンは、どんな幅でも3行で表示: `既定値` / `(n)` / `に戻す` |
| アプリ（一覧・管理） | 「放置」「孤立」のバッジは公開名の下に常に表示。更新日は「日付1つ」の規則（09） |
| 端末・アプリ・お知らせの行の操作 | すべてアイコンのみ、行内で横並び、表の中で位置を揃える（09） |
| 日付の表示（全画面） | 09 の規則 |
**「新しいお知らせ」ダイアログの構成**（編集時は見出しを「お知らせを編集」）
```
# 新しいお知らせ
## 種別        （プルダウン）
## 重要度      （プルダウン）
## タイトル    （入力欄）          ← 17 M39 の判断で残す（16 の確認事項 Q22）
## 本文        （入力欄）
## 表示の開始  （日付入力）  ┐ 横に並べる
## 表示の終了  （日付入力）  ┘
## 対象        （プルダウン）
### 警告内容   （入力の誤りがあるときだけ表示。例: 本文が空、期間の前後が逆）
## 表示の確認  （ホームでの見え方のプレビュー）
```
枠で囲むのは（）の中の部品だけ。見出しの文字は枠の外。
