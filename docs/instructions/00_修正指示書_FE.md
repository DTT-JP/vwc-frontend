## 0. 守ること

1. **各 Part は、順に、別のリリースとして行う。** 混ぜない。BE の対応する版が先に配備されていること（`rules/05`）。
2. BE・IdP のファイル（PHP）を FE のリポジトリに入れない（B3）。FE は IdP の API を呼ばない（B15）。FE がするのは、BE の入口（`system/auth/idp.php`）への**画面遷移**と、`?auth=` への反応だけ。
3. FE に、パスワードの入力欄を置かない（B17）。
4. BE が知っている入力キーだけを送る（A16）。新しい任意のキーは、`meta/version` の `backend.apis` の `params` を確認してから送る。
5. 自作ファイルの先頭に `SPDX-License-Identifier: GPL-3.0-or-later`（B10）。第三者の部品（`vendor/`）は触らない。
6. `public/config.js`（環境ごとの設定）は、リポジトリに入れない。新しい設定キーは、**省略しても動く**（既定値を持つ）ようにする。
7. 実装した内容が、決めた値と違ったら、先に報告する。

## Part B: 互換判定と API 管理（FE 1.1.0）

ルールは `docs/rules/04_API規則.md`・`rules/03` §3。

### B1. 互換判定（`js/boot.js`・`js/compat.js`・`js/data.js`）

現行: `boot.js` の `EDITOR_CONFIG.requiredApi`（整数）と `meta/version` の `api_version` を比べ、違えば全画面を止める（101行付近）。`data.js` の `meta` は `{api_version, server_version, features}`。

1. `meta` に `backend`・`login_providers` を足す（`meta/version` の応答から読む。無ければ空）。
2. **BE の MAJOR**: `backend.version` があれば、その MAJOR。なければ（旧 BE）、`api_version`。FE の MAJOR は `public/VERSION` から。**MAJOR の不一致は、現行どおり全体を止める。**
3. `requiredApi` は、FE 1.x の間は残し、`api_version` との比較も**併せて行う**（旧 BE との互換）。`config.sample.js` の `requiredApi` は、そのまま。
4. **API の存在の確認（機能一覧方式）**: FE が使う API 名の一覧（`USED_APIS`。名前 → その API を使う機能の名前）を、`js/compat.js` に持つ。起動時に、`backend.apis` にない API があれば、該当する機能だけを無効にし、警告を表示する（原文 §3 の「部分互換」）。
5. `deprecated` の API を使っていれば、開発者向けにコンソールへ警告を出す（`rules/04` §8）。
6. `meta/version` の取得に失敗したら、バージョン表示を「取得できません」とし、アプリ本体は動かす（原文 §7-5。現行の動作を変えない）。
7. BE が知らない入力キーを送らない（A16）。現行の FE が送るキーは、BE 1.0.0 のすべてのキーが BE にあるため、変更は不要。**将来**新しいキーを送るときのために、`api.js` の呼び出しの前に `backend.apis[名前].params` を確認する仕組み（小さな関数）を用意する。

## Part C: IdP ログイン（FE 1.2.0）

前提: BE 1.2.0 が配備済み（IdP も）。ログインの方式の一覧は `meta/version` の `login_providers`（`["idp","microsoft"]` など）。

### C1. ログイン画面（`index.html` の `t-login`・`js/screens.js`・`js/boot.js`）

- 現行のタブ: `qr`（QR コード）・`code`（数字コード）・`ms`（MS アカウント）。`ms` のタブと、`#ms-login`・`.ms-signin`・`.ms-hint` の文言を、**方式ごとに出し分ける**。
  - `login_providers` に `idp` があれば、新しいタブ（`data-t="idp"`。文言は「部活アカウント」）を出す。ボタンは `Api.idpUrl('direct')`（初回の端末の登録は `Api.idpUrl('register')`）へ遷移する。
  - `login_providers` に `microsoft` があれば、現行の `ms` のタブを出す。
  - 既定で開くタブは、`login_providers` の最初の方式。`openLogin('ms')`（`boot.js` 142行付近）を、その方式に直す。
- パスワード入力欄を、FE に作らない（B17）。ボタンを押すと、IdP の画面へ遷移する。

### C2. `js/api.js`

`microsoftUrl(mode)`（118行付近）は残し（2.0.0 まで）、`idpUrl(mode)` を足す。`mode` は `direct` `register` `reauth` `logout`。URL は `system/auth/idp.php?mode=…`（`microsoftUrl` と同じく、`apiBase` から作る。`rules/04` §11）。

### C3. 再認証のポップアップ（`js/admin.js`）

- 現行（40行付近）の `window.open(Api.microsoftUrl('reauth'), …)` を、**その部員が IdP に結び付いているか**（`me` の `member.idp_linked`。`js/data.js` の部員の正規化に `idpLinked` として足す）と `login_providers` で選ぶ。結び付いていれば `Api.idpUrl('reauth')`、そうでなければ `Api.microsoftUrl('reauth')`。
- 同一オリジンのポップアップなので、IdP への遷移・戻りの間も `window.opener` が保たれる見込み（計画 U6）。**実機で、再認証のポップアップが、元のウィンドウへ戻る**ことを確認する。
- `reauthUntil` の扱い（`data.js` の秒→ミリ秒の正規化）は変えない。
- 冒頭のコメント（12行）の「Microsoft の直接ログイン」を、方式に依存しない書き方に直す。

### C4. エラーの表示（`js/boot.js`・`js/app.js`）

- `boot.js` の `KEY`（145行付近。`reason` → コード）に、`contract: 'E-A20'`・`connect: 'E-A21'`・`verify: 'E-A22'`・`sub_mismatch: 'E-A23'`・`inactive_idp: 'E-A24'` を足す。BE が `code` を付けて返すので、通常は `q.get('code')` が使われる。未知のコードは、現行どおり `E-A99` に落とす。
- `app.js` の `ERROR_CATALOG`（40〜52行付近）に、`E-A20`〜`E-A24` を足す。文言の案:
  - `E-A20`: 「認証システムとエディターの版が合いません。管理者に連絡してください。」
  - `E-A21`: 「認証システムに接続できません。少し待ってやり直してください。続く場合は管理者へ。」
  - `E-A22`: 「認証システムからの情報を確認できませんでした。もう一度ログインしてください。」
  - `E-A23`: 「この部員は、別のアカウントに結び付いています。管理者に連絡してください。」
  - `E-A24`: 「このアカウントは無効になっています。管理者に連絡してください。」
- `E-A01`〜`E-A15` のうち、「Microsoft」と書いている文言は、FE 1.2.0 では、方式に依存しない書き方（「ログイン」）にする。2.0.0 で、使わなくなったものを削る。
- BE の新しいエラー `managed_by_idp`（409）を、`app.js` のエラー表（20行付近の `reauth_required: ['E-P03', …]` の形）に足す。コードは、既存の最大番号（`E-P21`）の次、`E-P22`。文言の案: 「この部員の管理者の設定は、認証システム（IdP）の管理画面で行います。」

### C5. 管理画面（`js/admin.js`）

- 部員の「管理者」のチェック（`mem-adm`。290行付近）と、部員の追加・編集のダイアログの `is_admin`（311〜312行付近）: **結び付いた部員（`idpLinked`）では、無効にし**、「管理者の変更は認証システム（IdP）の管理画面で行います」と表示する。BE は、現在の値と同じなら受け付けるので、FE が更新のたびに送る現在の `is_admin` は、そのままでよい。
- 管理画面に、「認証システム（IdP）の管理を開く」リンクを足す（新しいタブ。`rel="noopener"`）。URL は、`config.js` の任意の設定 `idpBase`（既定: `../auth/`、`location` からの相対）から作る。`config.sample.js` に、`idpBase` を**任意**として足す（省略しても動く）。FE が IdP を呼ぶわけではなく、画面遷移だけ（B15）。
- CSV の取り込みで、BE の応答に `ignored_admin` があれば、「管理者権限の列は無視しました（認証システムで設定してください）」と表示する。

### C6. ログアウト

BE の `auth/logout` が成功した後、その部員が IdP に結び付いていれば、`Api.idpUrl('logout')` へ遷移して、IdP のセッションも終える（戻り先は BE が決める）。

### C7. 文書とヘルプ

- `public/help/14-admin.md`（Microsoft への言及が1か所）を、IdP の説明に直す。ほかにヘルプ・`docs/` で「Microsoft」「MSアカウント」「サインイン」を探して、直す（`grep` で確認する）。

- `docs/api-assumptions.md` の Microsoft の言及を直す。
