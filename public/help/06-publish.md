# 公開とアプリ

{icon:public} 公開で、プロジェクトをアプリとして公開したり、公開済みのアプリを更新・ロールバックできます。

## 公開状態は3つ
| 状態 | 見られる人 |
|---|---|
| **公開** | 誰でも |
| **限定公開** | アクセスコード（8桁の数字）を知っている人 |
| **非公開** | 指定した部員だけ（ログインが必要） |

> [!NOTE] 「アプリ」と呼ぶ理由
> 公開状態にかかわらず、仕様上の用語は「アプリ」です。

状態を切り替える前に確認が出ます。切り替え中は一時的に閲覧できない場合があります。

## 新しく公開する
「新しく公開」を押すと、次の順に進みます。

1. **公開名**を決める：英小文字・数字・ハイフン・アンダースコアの3〜30文字です。先頭と末尾は英数字にします。記号の連続も使えます。`admin` `api` `login` など予約語と、すでに使われている名前は使えません（入力しながら理由を確認できます）
2. **プロジェクト**と**コミット**を選ぶ：コミット候補は選んだプロジェクトの履歴だけです。部員は自分のプロジェクトと、公開権限をもらった共有プロジェクト、管理者は全員分から選べます
3. **公開状態**を選ぶ
4. **公開前の確認**：公開範囲、公開するファイルの数とサイズ、**公開されないファイル**（`.` で始まる隠しファイル、実行できる形式のファイル）。それ以外は、選んだコミットのファイルがすべて複製されて公開されますを見て、「公開する」を押します
5. **結果**：URL、公開されなかったファイル、限定公開ならアクセスコードが表示されます

> [!WARNING] サイズの上限
> 公開できるのは、管理設定の「アプリの最大サイズ」までです。超えると「公開する」は押せません。

## 公開済みアプリ
アプリの一覧には固定コミット、更新日、サイズ、URLがあります。URLはコピーでき、「開く」から詳細を表示できます。このモックでは、サーバー配信は行わず、開く操作を画面上で再現します。

## アクセスコード
8桁の数字です。「1234 5678」のように4桁ずつ表示します。入力するときは数字だけを打てば、空白は自動で入ります。コピーしたときは、空白のない8桁になります。

> [!WARNING] アクセスコードの再生成
> 再生成すると、{red}いままでのコードでは入れなくなります{/}。「旧コードは無効になりました」と表示されるので、必要な人に新しいコードを伝え直してください。

アクセスコードの入口で間違えられる回数には上限があります（管理設定の「アクセスコードの失敗上限」）。超えるとロックされます。

## 更新とロールバック
アプリの管理を開き、コミットを選びます。選ぶと、現在の版との**変更の概要**（コミット数、追加・変更・削除のファイル数）が出ます。

- **更新**：新しいコミットに入れ替えます。`app.json` の `preserve` に書いたファイルは引き継がれ、**実際の一覧**が確認画面と結果に出ます
- **ロールバック**：以前のコミットに戻します。確認画面に、戻り先のコミット（番号・名前・作った人・日時）が出ます

```json
{
  "name": "portfolio-site",
  "preserve": ["data/", "uploads/"]
}
```

> [!NOTE] app.json を読み取れないとき
> 書式が壊れていると「読み取れません」と表示し、一覧は出しません。直してからもう一度開いてください。
